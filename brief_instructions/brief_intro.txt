OPEN-NFTs 项目全面总结
一、项目定位
OPEN-NFTs 是一个 NFT 潮玩创作平台，核心功能是让用户通过 AI 辅助创建独一无二的数字潮玩藏品，与藏品进行人格化对话，并为其申请链上唯一身份认证。
二、技术选型
层次	技术	版本	说明
框架	Next.js (App Router)	16	全栈框架，API Routes 做后端代理
核心	React	19	组件化开发
语言	TypeScript	5	strict 模式，无隐式 any
UI	shadcn/ui (Radix UI)	—	60+ 组件，位于 src/components/ui/

运行时	Node.js	24	沙箱环境预置
包管理	pnpm	—	严禁 npm/yarn
端口	5000	—	统一端口，HMR 热更新

四、核心数据结构
Collectible（藏品）
interface Collectible {
  id: string;                          // 唯一标识
  metadata: {
    createdAt: string;                  // 创作时间
    author: string;                     // 作者
  };
  name: string;                        // 名称
  intro: string;                       // 一句话介绍
  appearance?: string;                 // 外表描述（次要数据）
  story: string;                       // 背景故事（次要数据）
  character: string;                   // 性格特征（次要数据）
  sprites: string;                     // 藏品图片URL（S3，关键数据）
  persona: string;                     // 人格锚点（关键数据，对话核心依据）
  memory: string[];                    // 对话记忆（关键数据）
  nftStatus?: NftStatus;              // NFT申请状态
  nftId?: string;                      // NFT-ID编号
  nftApplyTime?: string;              // 申请时间
  nftTxHash?: string;                  // 链上交易哈希（预留）
  nftBlockNumber?: number;            // 区块号（预留）
}
三类关键数据：sprites（藏品动画 / 图片）、persona（人格锚点）、memory（对话记忆）
三类次要数据：intro（一句话介绍）、story（背景故事）、character（性格特征）
数据关系：persona 是由 AI 根据 appearance + story + character 三项生成的深度人格画像摘要。对话时 LLM 仅读取 persona，不直接读取 story/character。
NftStatus 状态枚举
none → pending_audit → approved → minted
                        ↓
                     rejected → (可重新申请)

5.3 AI 调用流程详解
万物潮玩（照片创建）
用户拍照 + 输入 [名称, 介绍]
        │
        ▼
① POST /api/upload-image (FormData: image=照片)
   → S3Storage.uploadFile() → presignUrl(7天)
   → 返回 { imageUrl: "https://s3.xxx/..." }
        │
        ▼
② POST /api/generate-content (FormData: image=照片, name, intro)
   内部流程：
   a. 先将照片上传到S3获取HTTP URL（豆包LLM不接受data URI）
   b. LLMClient.invoke([
        { role: 'system', content: GENERATE_CONTENT_SYSTEM },
        { role: 'user', content: [
            { type: 'text', text: generateContentUser(name, intro) },
            { type: 'image_url', url: s3Url }
        ]}
      ], { model: 'doubao-seed-2-0-pro', thinking: 'enabled' })
   c. 旗舰模型失败 → 降级 doubao-seed-1-8
   → 返回 { appearance, story, character }
        │
        ▼
③ 用户编辑/润色 appearance / story / character
        │
        ▼
④ 并行调用两个API：
   ┌─ POST /api/generate-sprites
   │  { name, intro, appearance, story, character, imageUrl(原始照片S3 URL) }
   │  → ImageGenClient.generate({
   │       prompt: generateSpritesPromptFromImage(name,intro,appearance,story,character),
   │       image: imageUrl,    ← 图生图：参考原始照片
   │       size: '2K'
   │    })
   │  → removeWhiteBackground(spritesUrl) → PNG dataURL
   │  → POST /api/upload-image ({ imageDataUrl }) → S3 URL
   │  → 返回 sprites S3 URL
   │
   └─ POST /api/generate-persona
      { appearance, story, character }
      → LLMClient.invoke([
           { role: 'system', content: GENERATE_PERSONA_SYSTEM },
           { role: 'user', content: generatePersonaUser(appearance, story, character) }
         ], { model: 'doubao-seed-1-8', thinking: 'enabled' })
      → 返回 persona 文本
        │
        ▼
⑤ 构造 Collectible 对象 → localStorage.setItem()
自由创作
用户输入 [名称, 介绍]
        │
        ▼
① (可选) 点击"AI补全" → POST /api/generate-free { name, intro }
   → LLMClient.invoke([system + user], { model: 'doubao-seed-1-8', thinking: 'enabled' })

        │
        ▼
② 用户编辑
        │
        ▼
③ 并行调用（同万物潮玩④，但 generate-sprites 无 imageUrl 参数）

     })
   → 透明化 → 上传S3
   + generate-persona
        │
        ▼
④ 保存到 localStorage
对话模式
POST /api/chat { message, persona, memory, history }
        │
        ▼
① 构造消息列表：
   [
     { role: 'system', content: chatSystemPrompt(persona, memory) },
     ...history(当前会话上下文),
     { role: 'user', content: message }
   ]
        │
        ▼
② LLMClient.invoke(messages, {
     model: 'deepseek-v3-2-251201',

        ▼

六、提示词外置管理
所有 AI 提示词集中在 src/lib/prompts.ts，运行时从该文件读取。修改提示词只需编辑此文件。
编号	导出名	用途	模板参数
1	GENERATE_CONTENT_SYSTEM + generateContentUser(name, intro)	万物潮玩文本生成	name, intro
2	GENERATE_FREE_SYSTEM + generateFreeUser(name, intro)	自由创作 AI 补全	name, intro
3a	generateSpritesPromptTextOnly(name, intro, appearance, story, character)	纯文生图提示词	5 项全部
3b	generateSpritesPromptFromImage(name, intro, appearance, story, character)	图生图提示词	5 项全部 + "必须以参考图片为原型"
3	generateSpritesPrompt(name, intro, appearance, story, character, hasImage)	兼容入口，根据 hasImage 选择 3a/3b	+ hasImage
4	GENERATE_PERSONA_SYSTEM + generatePersonaUser(appearance, story, character)	人格锚点生成	appearance, story, character
5	chatSystemPrompt(persona, memory?)	对话模式系统提示	persona + 最近 20 条 memory
6	FALLBACK_CONTENT / FALLBACK_PERSONA / FALLBACK_SPRITES_PROMPT	错误降级	—
特殊要求：3a/3b 的图片提示词中包含 "背景必须是纯白色 (#FFFFFF)" 强制要求，为后续白色背景透明化做准备。
七、图片透明化处理（方案 B）
src/lib/removeBackground.ts
原理：豆包生图时提示词要求纯白色背景 → 前端 Canvas 容差透明化
算法：
加载图片到 Canvas，获取 ImageData
第一遍扫描：计算每个像素与纯白 (255,255,255) 的 RGB 欧氏距离
dist ≤ tolerance(30) → 标记为完全透明 (mask=1)
tolerance < dist ≤ tolerance + featherRadius*10 → 线性过渡部分透明
第二遍扫描：从透明像素向 featherRadius(2px) 范围内的非透明像素扩散羽化
输出 PNG dataURL（保留 alpha 通道）
后续处理：透明化后的 PNG dataURL 上传到 S3，localStorage 只存 S3 URL。
展示：DetailPage / CollectionPage 中图片使用棋盘格背景（灰白交替）可视化透明区域。

8.2 .onft 打包格式（已实现，本地导出 / 导入可用）
src/lib/storage/onft-format.ts
┌──────────────────────────────────────────┐
│  Header (固定 64 bytes)                   │
│  ├─ Magic: "ONFT" (4 bytes)              │ ← 文件标识
│  ├─ Version: uint16 (2 bytes)            │ ← 格式版本号，当前 1
│  ├─ JSON Length: uint32 (4 bytes)         │ ← 元数据JSON长度
│  ├─ Image Length: uint32 (4 bytes)        │ ← 图片数据长度
│  └─ Reserved: (54 bytes)                 │ ← 预留扩展
├──────────────────────────────────────────┤
│  JSON Payload (变长)                      │
│  └─ Collectible 对象（不含 sprites URL）  │ ← 元数据
├──────────────────────────────────────────┤
│  Image Payload (变长)                     │
│  └─ 透明化后的 PNG 二进制数据              │ ← 藏品图像
└──────────────────────────────────────────┘
工具函数：
packOnft(json, pngBuffer) → Blob：打包
unpackOnft(buffer) → { json, pngBuffer }：完整解包
readOnftMeta(buffer) → json：仅读取元数据，不解图片
